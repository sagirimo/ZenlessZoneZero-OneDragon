# 独立战斗助手

## 使用范围

用户手动进入关卡，助手只执行自动战斗。双击根目录 `启动战斗助手.cmd`，选择策略，再开始。开始/暂停和停止热键显示在窗口按钮上。游戏保持 1920×1080，键位与助手设置一致。

按 F9 开始、暂停或继续，按 F10 停止（沿用现有热键配置，以窗口显示为准）。操作菜单、切换窗口或处理结算前先暂停。若游戏以管理员身份运行，助手也需要右键选择「以管理员身份运行」。

独立入口复用现有自动战斗 Application、角色识别、闪避模型和策略文件。它只注册自动战斗，不进入日常、刷本或登录流程，也不检查代码更新。它仍依赖本目录中的源码、资源和 Python 环境，不能把启动文件单独移走。

## 设计

### 精简界面

参考 [BetterGI](https://github.com/babalae/better-genshin-impact) 的 Windows Fluent 布局，使用浅灰背景、白色卡片、蓝色主按钮和左侧导航。仅保留「自动战斗」「设置」「日志」三个页面，保持原项目的版权与许可证，不使用 BetterGI 的标志或插画。

首页只放策略、终结技和启动控制；截图频率、运算设备、游戏键位移到设置页。状态与开始/停止按钮固定在底部，切换页面后仍能停止战斗。

界面刷新由运行状态事件驱动。空闲时不启动状态轮询；日志使用有界缓存，仅在日志页可见时按批更新，隐藏时停止刷新。关闭与取消期间短暂启用停止检查，线程退出后立即关闭。以上只减少界面开销，不等同于已测得实战帧率改善。

### 战斗与生命周期

- 专用上下文只初始化画面区域与控制器。手动战斗调用不请求结算、距离 OCR，因此不初始化 OCR，不触发 OCR 模型迁移；不初始化地图、手册、插件、推送和遥测。
- 专用工厂沿用自动战斗应用，清除自动登录操作。未找到游戏时直接报告失败。
- 战斗设置保存到当前账号的 `battle_standalone.yml`。首次从原战斗配置读取策略、终结技和截图间隔；固定前台键鼠模式。原战斗配置保持独立。
- 游戏键位复制到 `battle_standalone_game.yml`，可在专用窗口中调整；不会修改游戏内键位或完整版配置。全局后台模式不会触发虚拟手柄初始化。
- 运算设备设置保存到 `battle_standalone_model.yml`。窗口可切换 CPU / GPU 闪光识别，使用现有模型文件。
- 初始化、战斗运行都在工作线程执行。Qt 控件只由主线程更新。重复开始不创建第二个任务；停止和关闭等待运行线程退出，再释放资源。
- 热键只发 Qt 信号，由窗口统一处理，避免监听线程直接访问界面。运行失败显示原因，并保留日志。
- 启动脚本直接调用本地 Python，不执行环境同步。依赖缺失时显示安装入口；首次安装与日常启动分开。

## 环境与验证

首次执行 `安装战斗助手.cmd` 准备 Python 3.11 与项目运行依赖，无需预装 Python。脚本下载固定版本 uv 官方 Windows x64 包并校验 SHA-256，然后按锁文件安装。环境位于 `.venv`，下载缓存位于 `.install`。安装过程需要网络，日常启动不主动更新代码或依赖。战斗模型仍由原框架加载，缺失模型需要准备好后再使用。

测试位于独立测试仓，覆盖初始化失败、未开游戏、重复启动、关闭等待、配置隔离、运行错误显示、跨线程状态更新、固定运行按钮、日志缓存上限与隐藏日志停止刷新。离线界面测试不能替代实战验证；角色策略命中率、闪避成功率和连携时序需在真实游戏中检查。

战斗画面定义见 [战斗画面](../../game/screens/战斗画面.md)，现有识别机制见 [自动战斗](auto_battle.md)。本入口不改变技能循环和画面判定规则。
